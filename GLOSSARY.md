# Waveform Manual Terminology Glossary

Companion to `STYLE.md`: STYLE.md covers voice, punctuation and gating, and this file fixes the words.

## Owner decisions (2026-10-17)

Where these decisions conflict with the tables below, they take precedence.

- **J1:** The bottom panel is the **Detail Editor**, not "Content Editor". When telling the reader how to open it, quote the View menu item exactly as the app shows it.
- **J2:** **Browser** means the whole side container. The search tool is the **Search tab**, and its left column is the **category list**. Don't use "sidebar" or "side panel".
- **J3:** Write **Edit**, the document, with a capital E.
- **J4:** Quote Quick Actions menu items exactly as shown ("Show Quick actions bar"). In prose, write **Quick Actions bar** and **Quick Actions window**.
- **J5:** Use **cursor** in prose. Write "playhead" only when quoting a setting name that contains it.
- **J6:** Write **In marker** and **Out marker**, with no hyphen, as the app does.
- **J7:** Call the panel-selector button the **eye button**.
- **J8:** Capitalise clip types: **Audio clip**, **MIDI clip**, **Step clip**.
- **J9:** After the first full name in a section, short plugin names are fine ("MIDI Arpeggiator", then "Arpeggiator").
- **J10:** Write **Volume & Pan**.
- **J11:** Call the File / Edit / Options ... menus at the top the **main menu**, not "menu bar".
- **J12:** Order modifier keys as the app shows them: Mac `Ctrl + Shift + Opt + Cmd + K`, Windows `Ctrl + Shift + Alt + K`.
- **J13:** Put control and button names in **bold** and menu paths in *italics*, for example *View > Show Mixer*. Settings paths are menu paths too: *Settings > General*.
- **J14:** Write "quantise", "quantising" and "quantisation" in prose. The chapter title is "Quantising MIDI Notes". The file name stays `quantizing-midi-notes.md` so the URL doesn't change.
- **Edition lines:** Use the form in STYLE.md, `> 📝 **Edition:** ...`, placed directly under the badged heading. This replaces the "Available in ..." shapes in the formats section below.
- **J15:** Quote UI labels exactly, including US spellings such as "Synthesizer", "License" and "Analyzer". Use British spelling in prose.

**Evidence paths** are relative to `waveform/common/Source/` unless they start with `modules/`. Quoted strings are the exact `TRANS()` / `NEEDS_TRANS()` text.

**Rule of thumb for UI names.** Copy the noun phrase the UI uses. When the UI name is a proper name plus a generic noun, capitalise the proper name and lower-case the generic noun: "Actions panel", "Plugin panel", "Quick Actions bar", "Folder track", "Step clip", "Render dialog". When there is no proper name, lower case: "transport bar", "menu bar", "inline mixer", "track header", "cursor". Title case is only for headings and chapter titles. Quote menu items, buttons and settings exactly as the UI spells them, even when that breaks these rules (**Show Quick actions bar**, **Show Inline mixer**).

## (b) Formats

### Menus and menu paths

- **Top-level menus in the Edit tab** (exact names, `ui/mainwindow/EditTab.cpp:1755-1770`): **File**, **Edit**, **Options**, **Automation**, **Click**, **Snap**, **Sync**, **Track**, **Video**, **View**, **Help**, **Actions**. The Projects tab adds **Project** (`ui/mainwindow/ProjectTab.cpp:648`). There is no Tools, Window, Settings or Preferences menu, and no "Run Script" button. In prose: "the View menu".
- **Separator:** ` > ` with a space either side: `File > Export > Render to a file`. Never `→` (0 menu uses left), `->`, `/` or `>` without spaces (about-this-book.md "Settings>Appearance").
- **Emphasis:** one bold span around the whole path: **View > Show Mixer**. Today the manual has 86 italic paths (`*A > B*`, mostly older chapters: reference-settings, edit-tab, recording-audio, audio-clips-and-editing-audio) and 29 bold ones (newer chapters). See J13.
- **Settings pages** use the same form: **Settings > Audio Devices**, **Settings > Keyboard Shortcuts**. A setting inside a page: "**Settings > General**, **Paste at edit cursor**" or "the **Paste at edit cursor** setting on the General page".
- **Ellipsis:** copy the UI, which always uses three full stops (`Edit custom macro commands...`). The docs have 27 Unicode `…` (working-with-video 8, importing-and-exchanging-projects 7, midi-setup 5) against 64 `...`.
- **Right-click menus:** "right-click the clip and choose **Rename**". Call it the **right-click menu** (17 hits) rather than "context menu" (16, step-clips 12) or "pop-up/popup menu" (8). A list control is a **dropdown** (11), not "drop down" (4).

### Keyboard shortcuts

- **Pairs:** Mac first, then Windows, separated by ` / `, each side complete: **Cmd + Z / Ctrl + Z** (39 hits, the convention set out in introduction.md and STYLE.md). Variants to fix: Windows first (1, using-plugins), combined `Cmd/Ctrl + Z` (1, reference-settings), tight `Cmd+Z` / `Shift+C` (2, chord-track), `(Windows) / (Mac)` suffixes (4: installing-the-demo-projects, introduction, reference-settings, chord-track), lower-case `ctrl` (1, comping). `⌘` is gone.
- **Spaces around `+`** inside a chord (`Cmd + Shift + Z`). This matches how the app prints shortcuts (`command + Z`, JUCE `juce_KeyPress.cpp:249-256`).
- **Modifier-only pairs:** "hold **Cmd / Ctrl**" (21), "hold **Opt / Alt**" (10). Same Mac / Windows order.
- **Click and drag with a modifier:** hyphenate and pair: "Cmd-click / Ctrl-click", "Opt-drag / Alt-drag". Avoid `Cmd/Ctrl-click` (2, browser).
- **Key names:** **Cmd**, **Ctrl**, **Opt**, **Alt**, **Shift** (introduction.md "Modifier Keys Conventions"). Not "Option" (4: chord-track, recording-audio, visual-plugin-selector), "Command", "Control" or "Meta" except in the Linux note. On Windows the Mac **Opt** becomes **Alt** and **Cmd** becomes **Ctrl**; check the app's mapping when Mac uses Ctrl.
- **Multi-modifier order:** as the app shows it (JUCE order): Mac `Ctrl + Shift + Opt + Cmd + K`, Windows `Ctrl + Shift + Alt + K`. The docs currently mix "Opt + Cmd + T" and "Cmd + Opt". See J12.
- **Single keys:** plain capital, no code font: "press **D**", "**F9**", "**Delete** or **Backspace**", "**Space bar**", "**Return**". Function keys always with F.
- introduction.md:106 says "the convention Mac / PC"; write "Mac / Windows" (Linux follows Windows).

### Capitalisation of UI names

1. Exact UI label in bold when the reader clicks or reads it: **Show Content Editor**, **Snap**, **Paste at edit cursor**.
2. Named panels, windows and objects in running prose: proper name capitalised, generic noun lower case (see the table): Actions panel, Plugin panel, Quick Actions bar, Quick Actions window, Rack editor, Render dialog, Edit tab, Folder track, Step clip, MIDI clip.
3. Plain nouns without a proper name: transport bar, menu bar, track header, inline mixer, cursor, marked region, clip launcher, eye button.
4. Single-word proper names: Browser, Mixer, Edit (the document), Project (the container).
5. Tabs of the Browser: "the **Search** tab", "the **Markers** tab". Modes of the Content Editor: "the **Clip** tab".
6. Headings and chapter titles use title case ("The Actions Panel", "Folder Tracks"); prose under them does not.

### Writing edition and expansion names

- Editions: **Waveform Pro**, **Waveform Free**, **Waveform OEM** in full on first mention in a chapter, then **Pro**, **Free**, **OEM**. Lists ascend: "Free, OEM and Pro". Never "PRO" or "FREE" in prose (the badge text is the only all-caps PRO), never "Pro version", "Free version", "Pro-only" (4) or "(Pro edition)" / "(Pro)" heading suffixes.
- Expansions: full product name with capital **Expansion** every time: "the MIDI Producer Expansion", "the Pro Video Expansion". Do not share the suffix across a list ("MIDI Producer / Synth Pack expansions", 2 in samplers-and-instruments): write "the MIDI Producer Expansion or the Synth Pack Expansion". Generic plural stays lower case: "expansions", "content packs" (matches `ui/settings/LicensingSettingsPanel.h:251`). Not "add-on" (2) or "Expansion Pack".
- Gating markup (STYLE.md): heading badge `<span class="pro">PRO</span>` plus one line directly under the title, using one of these shapes:
  - "Available in Waveform Pro."
  - "Available in Waveform Pro, or with the Recording Engineer Expansion."
  - "Available in Waveform Pro, or with the MIDI Producer Expansion or the DJ Mix Tools Expansion."
  - "Available in every edition." (only where a reader would otherwise assume Pro)
- Stem separation downloads are **feature packs**; their folder setting is **Feature Extensions** (Settings > File Locations).
- Edition names inside **Settings > Advanced** feature-set choices are quoted as shown there (**Pro**, **OEM**, ...).
